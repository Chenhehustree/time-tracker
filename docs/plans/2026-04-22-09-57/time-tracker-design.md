## 1. 一句话总结

为个人工时追踪场景，使用 BlueprintUI 视觉系统重绘计时工具界面，解决已完成任务无法追加记录、时间段信息拥挤难操作的问题，同时补全任务删除/编辑、暗黑主题等基础功能。

## 2. 背景与问题（As-is）

- **当前做法**：单文件 HTML（3655行），纯原生 JS/CSS，Modern Dashboard 布局，任务卡片内嵌展示所有时间段及 24小时拖拽时间轴
- **痛点/成本**：
  1. Completed 任务为终态，无任何操作按钮，无法追加记录
  2. 时间段列表拥挤在卡片内部，短时间段（<30分钟）进度条几乎不可见
  3. 缺少任务删除、任务重命名等基础功能
  4. 单文件 CSS 无模块化，维护困难
- **为什么现在做**：用户明确要求 BlueprintUI 重绘，且上述痛点直接影响日常使用效率

## 3. 目标（Goals）

- [ ] 引入 BlueprintUI CSS，统一视觉风格（色彩、字体、间距、组件样式）
- [ ] Completed 任务支持"追加记录"，在该任务下新增时间段并开始计时
- [ ] 任务卡片默认精简展示，展开后进入独立面板查看完整时间段列表
- [ ] 独立面板内保留 24小时拖拽时间轴，宽度充足、可正常操作
- [ ] 增加任务删除（带确认）和任务名称编辑功能
- [ ] Dashboard 统计区使用 Blueprint Card/Callout 重新设计
- [ ] 支持明暗主题切换（Blueprint 原生支持）

## 4. 非目标（Non-goals）

- **不引入 React 或构建工具链**：保持纯 HTML/JS 单文件架构，仅使用 Blueprint CSS
- **不重构数据存储逻辑**：保留 localStorage 按日期隔离的存储方式
- **不新增报表/图表功能**：周/月统计图表不在本次范围内
- **不改动休息时段计算逻辑**：现有有效时长计算规则保持不变
- **不开发移动端适配**：Blueprint 为桌面优先，本次仍聚焦桌面端体验

## 5. 目标用户与使用场景

### 5.1 用户画像

- **P1：个人开发者/自由职业者** — 需要追踪每日在各项目上的工时，便于后续结算或复盘。关键痛点是任务频繁切换、需要追加记录已完成的任务。

### 5.2 典型场景

- **S1：开始新任务** → 在 Dashboard 输入任务名 → 点击"开始" → 任务进入 running 状态，卡片高亮显示 → 顶部 Banner 显示当前计时任务
- **S2：暂停后继续** → 点击"暂停" → 任务变为 paused → 点击"继续" → 追加新时间段并恢复计时
- **S3：已完成的任务追加记录** → completed 任务显示"追加记录"按钮 → 点击后新增时间段并开始计时 → 完成后该任务下有多个独立的时间段记录

## 6. 用户旅程（To-be）

**主流程：任务计时与追加**

1. **用户打开页面** → 系统加载今日任务列表，统计卡片显示今日概况
2. **用户创建新任务** → 输入任务名，点击"开始" → 任务卡片进入 running 状态（Blueprint intent=success 样式），顶部 Banner 显示当前任务计时
3. **用户点击暂停** → 当前时间段结束，任务变为 paused（Blueprint intent=warning 样式）→ 卡片显示累计时长
4. **用户点击结束** → 任务变为 completed（Blueprint intent=none + 弱化样式），操作按钮变为"追加记录"
5. **用户需要追加记录** → 点击"追加记录" → 在该任务下新增时间段并开始计时 → 任务状态变为 running
6. **用户展开查看详情** → 点击"展开详情" → 下方滑出独立面板，展示所有时间段列表及 24小时时间轴
7. **用户调整时间段** → 在独立面板中拖拽时间轴手柄 → 系统检测冲突并保存

### 6.1 失败路径与边界

- **F1：时间段重叠冲突** → 用户拖拽时间轴导致与同一任务的其他时间段重叠 → 手柄变红提示冲突 → 用户调整后恢复
- **F2：误删任务** → 用户点击任务删除按钮 → 弹出 Blueprint 样式确认对话框"确定删除任务及所有时间段？" → 用户确认后才删除
- **F3：空任务名** → 用户尝试创建空名称任务 → 输入框边框变红（Blueprint `.bp5-intent-danger`），提示"请输入任务名称"

## 7. 约束与假设

### 7.1 约束（Constraints）

- **C1：纯 HTML/JS 单文件架构**：无法使用 Blueprint 的 React 交互组件（Dialog、Tree、Table 等），只能通过 CSS 类模拟视觉样式
- **C2：localStorage 存储限制**：单域名 5-10MB，无法存储大量历史数据
- **C3：桌面端优先**：Blueprint 组件库非移动优先，布局假设最小宽度 1024px

### 7.2 假设（Assumptions）

- **A1：用户主要在同一台电脑上使用** — 验证方式：localStorage 按设备隔离，若用户反馈数据不同步则说明需要云存储
- **A2：每日任务数量通常在 10 个以内** — 验证方式：若用户任务超过 20 个，卡片列表滚动体验会下降，需考虑分页或筛选
- **A3：用户对拖拽调整时间有需求** — 验证方式：若用户几乎不拖拽调整，则时间轴可以进一步简化

## 8. 方案选择

### 选择的方案：纯 HTML/JS + Blueprint CSS 渐进式重绘

- **做法**：
  1. 通过 CDN 引入 `@blueprintjs/core` CSS 文件
  2. 使用 Blueprint 工具类（`.bp5-card`、`.bp5-button`、`.bp5-tag`、`.bp5-intent-*` 等）替换现有组件样式
  3. 用纯 HTML/CSS 模拟 Blueprint 的 Card、Button、Tag、Callout 等静态组件外观
  4. 实现独立面板：点击"展开详情"后，在卡片下方展开全宽面板，内部使用 Blueprint 风格的列表和时间轴
  5. 状态机扩展：completed 任务增加 `canAppend` 判断，允许创建新 segment 并切换为 running
  6. 新增任务删除：卡片右上角增加 Blueprint 风格的"更多"菜单，内含删除选项
  7. 新增任务编辑：点击任务名变为可编辑输入框，失焦或回车保存
  8. 主题切换：在设置页面增加 toggle，切换 `bp5-dark` 类

- **优点**：
  - 保持"双击即用"的零依赖特性（除 CDN 外）
  - 视觉风格统一为专业级企业 UI
  - 风险可控，可逐步替换样式

- **缺点/风险**：
  - 无法使用 Blueprint 的交互组件，Dialog 需自行实现
  - 纯 CSS 模拟的组件可能与官方 React 组件有细微差异
  - 长期维护成本高于 React 方案

- **选择理由**：用户明确要求保持简单，不引入构建工具；当前痛点主要是视觉和交互层面，非架构层面

### 曾经考虑过的方案

- **React + Blueprint 完整重构**：放弃原因是用户选择保持纯 HTML/JS 架构

## 9. 核心对象/数据

不涉及数据模型变更，沿用现有结构：

- **Task**
  - **来源/归属**：浏览器 localStorage（`time-tracker-tasks-YYYY-MM-DD`）
  - **关键字段**：`id`, `taskName`, `status` (idle/running/paused/completed), `createdAt`, `segments[]`, `totalRawDuration`, `totalEffectiveDuration`
  - **生命周期**：创建 → 计时中（running）→ 暂停（paused）→ 完成（completed）→ 可追加记录（保持 completed 但允许新增 segment）

- **TimeSegment**
  - **来源/归属**：隶属于 Task 的 `segments` 数组
  - **关键字段**：`id`, `startTime`, `endTime`, `rawDuration`, `effectiveDuration`, `breakOverlapMinutes`
  - **生命周期**：创建（startTime）→ 进行中（endTime=null）→ 结束（填充 endTime，计算 duration）

## 11. User Stories（MVP）

### US-001: 已完成任务追加记录

- **作为**：已完成某个任务的用户
- **我想要**：在该任务下追加新的时间段记录
- **以便**：无需创建同名新任务，保持历史记录的连续性
- **验收标准**：
  - [ ] Completed 任务卡片显示"追加记录"按钮（Blueprint 风格）
  - [ ] 点击后创建新 segment 并将任务状态切换为 running
  - [ ] 追加的记录与原有记录在同一任务下展示
- **不包含**：修改已结束时间段的时长、合并任务
- **优先级**：P0
- **依赖**：无

### US-002: 展开独立面板查看时间段

- **作为**：需要查看任务详情的用户
- **我想要**：点击展开后在下方面板查看所有时间段
- **以便**：在充足的空间中查看和操作时间轴
- **验收标准**：
  - [ ] 任务卡片默认只展示任务名、状态、累计时长和最近一个时间段
  - [ ] 点击"展开详情"后下方滑出全宽独立面板
  - [ ] 面板内展示所有时间段列表，包含 24小时时间轴
  - [ ] 时间轴宽度不少于 700px，短时间段（15分钟）宽度至少可见
  - [ ] 再次点击可收起面板
- **不包含**：侧边抽屉、弹窗展示
- **优先级**：P0
- **依赖**：无

### US-003: 任务删除

- **作为**：需要清理无用任务的用户
- **我想要**：删除整个任务及所有时间段
- **以便**：防止已完成的任务无限累积
- **验收标准**：
  - [ ] 任务卡片右上角有"更多"菜单按钮
  - [ ] 菜单中包含"删除任务"选项
  - [ ] 点击后弹出确认对话框，显示"确定删除任务【XXX】及所有时间段？此操作不可恢复。"
  - [ ] 确认后任务从列表和 localStorage 中移除
- **不包含**：批量删除、回收站
- **优先级**：P1
- **依赖**：无

### US-004: 任务名称编辑

- **作为**：输入错误或需要调整任务名的用户
- **我想要**：直接修改任务名称
- **以便**：保持任务名的准确性
- **验收标准**：
  - [ ] 点击任务名称区域变为可编辑输入框
  - [ ] 失焦或按回车保存，按 Esc 取消
  - [ ] 空名称不允许保存，显示红色边框提示
- **不包含**：富文本编辑、任务描述字段
- **优先级**：P1
- **依赖**：无

### US-005: Dashboard 统计区 Blueprint 化

- **作为**：查看今日概况的用户
- **我想要**：统计卡片使用 Blueprint 视觉风格
- **以便**：获得更专业的视觉体验和更清晰的信息层次
- **验收标准**：
  - [ ] 4 个统计卡片使用 Blueprint Card + Callout 样式
  - [ ] 每个卡片包含图标、数值、标签
  - [ ] 使用 Blueprint 色彩系统（成功=绿色、警告=橙色、信息=蓝色等）
- **不包含**：新增统计维度、图表
- **优先级**：P1
- **依赖**：无

### US-006: 暗黑主题切换

- **作为**：在不同光线环境下使用的用户
- **我想要**：切换明暗主题
- **以便**：保护视力，适应环境
- **验收标准**：
  - [ ] 设置页面增加"主题"选项（明/暗/跟随系统）
  - [ ] 切换后全局应用 Blueprint 暗黑主题样式
  - [ ] 主题偏好保存到 localStorage，下次打开自动应用
- **不包含**：自定义主题色
- **优先级**：P2
- **依赖**：无

## 12. 成功标准

- [ ] Completed 任务可以成功追加记录，追加后状态变为 running
- [ ] 展开独立面板后，24小时时间轴在 15 分钟以上的时间段清晰可见
- [ ] 任务卡片默认视图的信息量减少至少 50%（不展开时不显示时间轴）
- [ ] 所有按钮、卡片、标签使用 Blueprint 视觉风格，与官方文档示例一致
- [ ] 任务删除操作有确认弹窗，误操作率降至接近 0
- [ ] 主题切换后所有元素正确适配暗黑模式，无样式错位

## 13. 风险与缓解

- **R1：Blueprint CSS 纯模拟与官方 React 组件存在视觉差异**
  - **缓解**：优先使用 Blueprint 的 CSS 工具类（`.bp5-*`），减少自定义样式；在常见分辨率下测试对比

- **R2：独立面板展开/收起动画与现有代码冲突**
  - **缓解**：使用 CSS max-height + transition 实现平滑动画，避免使用第三方动画库

- **R3：追加记录功能引入状态机 bug**
  - **缓解**：完整测试 completed → running → completed 的完整流程，确保总时长计算正确

## 14. 未决问题

- **Q1**：用户是否接受时间轴从 24小时制改为相对比例？（若测试中发现 24 小时制在面板内仍显拥挤）
- **Q2**：是否需要为独立面板增加"在新窗口打开"或全屏查看的选项？
- **Q3**：任务删除后，关联的历史日期记录是否同步删除？（当前按日期隔离存储）
