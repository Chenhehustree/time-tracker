## 1. 一句话总结
为个人工作者提供一个 Modern Dashboard 风格的工作计时器，以**任务为中心**组织多段计时记录，自动扣除固定休息时间，精准统计实际工作量并换算人天。

## 2. 背景与问题（As-is）
- **当前做法（V1）**：以"时间段"为中心，每次计时生成一条独立记录，任务名只是记录的一个字段
- **痛点**：同一任务多次计时时，记录分散在列表中，无法直观看到"某个任务今天总共做了多久"
- **为什么升级**：需要以任务为视角聚合查看工作量，更符合实际工作习惯

## 3. 目标（Goals）
- 以任务为中心组织所有计时记录，支持任务的暂停/继续
- 精确记录每个任务的多个工作时段，汇总计算任务总工时
- 自动扣除固定休息时段，计算有效工时
- 实时显示人天换算（按 8 小时/天）
- Modern Dashboard 风格的现代化 UI 体验
- 数据可导出备份（JSON 格式）

## 4. 非目标（Non-goals）
- 不支持多设备云端同步
- 不支持团队协作和多用户
- 不支持自动追踪（如检测空闲时间）
- 不支持发票/计费功能
- 不原生支持移动端（但 Web 可用）

## 5. 目标用户与使用场景
### 5.1 用户画像
- **P1 个人工作者/自由职业者**：需要精确追踪自己在各个项目上花费的时间，一个项目可能分多次完成

### 5.2 典型场景
- **S1**：开始任务A → 工作2小时 → 暂停（吃午饭）→ 继续任务A → 工作3小时 → 结束 → 查看任务A今日总耗时（扣除午休）
- **S2**：同时进行任务A和任务B（交替进行）→ 每个任务有自己的多段记录 → 分别查看各任务总耗时
- **S3**：月末汇总 → 查看所有任务的人天统计 → 导出数据备份

## 6. 用户旅程（To-be）

**核心操作流程：**

1. **打开应用** → 显示 Dashboard 概览（今日统计卡片、任务列表、当前进行中的任务）
2. **创建任务** → 点击"新建任务" → 输入任务名称 → 任务以卡片形式出现在列表中
3. **开始计时** → 在任务卡片上点击"开始" → 任务状态变为"进行中"，显示运行计时器
4. **暂停任务** → 点击"暂停" → 该任务新增一个已完成的时间段，任务状态变为"已暂停"
5. **继续任务** → 点击"继续" → 任务状态恢复"进行中"，开始新的一段时间计时
6. **结束任务** → 点击"结束" → 任务状态变为"已完成"，停止计时
7. **查看任务详情** → 展开任务卡片 → 查看该任务的所有时间段列表、原始总时长、有效时长
8. **查看 Dashboard 统计** → 页面顶部显示今日总有效工时、人天换算、任务数量
9. **查看历史** → 切换到历史视图 → 选择日期 → 查看当天的所有任务及汇总
10. **导出数据** → 点击"导出" → 下载 JSON 备份文件

### 6.1 失败路径与边界
- **F1 浏览器数据被清除**：用户误清缓存导致数据丢失 → 系统显示空状态 → 用户可通过之前导出的 JSON 恢复
- **F2 跨天计时**：用户在 23:59 开始计时，00:30 停止 → 系统应将记录归入开始的那一天
- **F3 计时期间页面刷新**：用户不小心刷新页面 → 恢复正在进行的任务计时状态
- **F4 休息时间内开始/继续任务**：用户在休息时段内操作 → 系统提示"当前为休息时间"并询问是否继续
- **F5 数据损坏**：localStorage 数据格式异常 → 系统检测并提示重置或恢复
- **F6 同一任务时间段重叠**：编辑时间后，同一任务的两个时间段出现重叠 → 系统提示冲突

## 7. 约束与假设

### 7.1 约束
- **C1 浏览器环境**：应用运行在浏览器中，依赖 localStorage 存储
- **C2 单用户**：设计为个人使用
- **C3 时间精度**：精确到分钟
- **C4 标准工作制**：人天换算固定按 8 小时/天计算
- **C5 单文件交付**：保持单 HTML 文件，内嵌所有资源（CSS/JS/图标字体）

### 7.2 假设
- **A1 用户主要在桌面浏览器使用**
- **A2 用户愿意手动导出备份数据**
- **A3 固定休息时间适用于大多数工作日**

## 8. 方案选择

### 选择的方案：单 HTML 文件 + Modern Dashboard UI + 任务为中心的数据模型

- **做法**：
  - 单 HTML 文件内嵌 CSS + JS（保持极简部署）
  - Modern Dashboard 视觉风格（深色侧边栏、卡片布局、数据可视化）
  - 以 Task 为中心的数据模型，每个 Task 包含多个 TimeSegment
- **优点**：
  - 以任务视角聚合时间，更符合实际工作习惯
  - 支持暂停/继续，一个任务可分多次完成
  - Dashboard 风格提供更清晰的数据概览
  - 仍保持单文件、零依赖、双击即用的特性
- **缺点/风险**：
  - 单文件代码量增加，但仍可控
  - Dashboard 风格需要更多 CSS，增加文件体积（预计 < 100KB）
- **选择理由**：
  - 用户明确反馈 V1 的"以时间段为中心"模型不够直观
  - Modern Dashboard 风格提升数据可读性和专业感
  - 保持技术方案的一致性（单文件、零依赖）

### 曾经考虑过的方案
- **方案 A：保持 V1 模型，仅改 UI**：无法解决"同一任务多段记录分散"的核心痛点
- **方案 B：使用前端框架（React/Vue）实现 Dashboard**：需要构建工具，违背"双击即用"原则

### 方案的比较

| 维度 | 方案 A（V1 改 UI） | 方案 B（框架） | 方案 C（选择） |
|------|-------------------|----------------|----------------|
| 解决多段计时痛点 | 否 | 是 | 是 |
| 部署复杂度 | 低 | 高（需构建） | 低（单文件） |
| UI 现代化程度 | 中 | 高 | 高 |
| 文件体积 | 小 | 大（+框架体积） | 中（纯 CSS+JS） |
| 离线可用 | 是 | 是 | 是 |

## 9. 核心对象/数据

- **任务（Task）**：
  - **来源/归属**：浏览器 localStorage，以日期为 key 存储
  - **关键字段**：
    - `id`（唯一标识）
    - `taskName`（任务名称）
    - `status`（状态：idle 未开始 / running 进行中 / paused 已暂停 / completed 已完成）
    - `createdAt`（创建时间戳）
    - `segments`（时间段数组，每个元素为 TimeSegment）
    - `totalRawDuration`（原始总时长，毫秒）
    - `totalEffectiveDuration`（扣除休息后的有效时长，毫秒）
  - **生命周期**：
    - 创建（新建任务）
    - 运行中（开始计时 / 继续计时）
    - 暂停（点击暂停，保存当前段）
    - 已完成（点击结束）
    - 归档（历史记录长期保留）

- **时间段（TimeSegment）**：
  - **来源/归属**：隶属于某个 Task
  - **关键字段**：
    - `id`（唯一标识）
    - `startTime`（开始时间戳）
    - `endTime`（结束时间戳）
    - `rawDuration`（原始时长，毫秒）
    - `effectiveDuration`（扣除休息后的有效时长，毫秒）
    - `breakOverlapMinutes`（与休息时段重叠的分钟数）
  - **生命周期**：
    - 创建（开始计时时创建，endTime 为空）
    - 完成（暂停或结束时填充 endTime 和时长）
    - 删除（用户手动删除该段）

- **休息时段（BreakPeriod）**：
  - **来源/归属**：应用全局配置
  - **关键字段**：`name`、`start`（HH:MM）、`end`（HH:MM）、`color`
  - **生命周期**：同 V1

- **今日汇总（DailySummary）**：
  - **来源/归属**：由当天所有 Task 的 segments 计算得出
  - **关键字段**：
    - `date`（日期）
    - `totalTasks`（任务数量）
    - `totalOnlineTime`（所有任务原始总时长）
    - `totalEffectiveTime`（所有任务有效总时长）
    - `manDays`（人天换算值）
    - `tasksBreakdown`（每个任务的贡献明细）

## 11. User Stories（MVP）

### US-001: 创建任务
- **作为**：用户
- **我想要**：创建一个新的工作任务
- **以便**：追踪该任务的所有工作时间段
- **验收标准**：
  - [ ] 点击"新建任务"按钮，输入任务名称后创建
  - [ ] 新任务以卡片形式出现在任务列表中，状态为"未开始"
  - [ ] 任务名不能为空，为空时提示用户
- **优先级**：P0
- **依赖**：无

### US-002: 任务多段计时（开始/暂停/继续/结束）
- **作为**：用户
- **我想要**：对同一任务进行多次开始-暂停-继续的操作
- **以便**：记录一个任务分多次完成的总耗时
- **验收标准**：
  - [ ] 点击任务卡片上的"开始"，任务状态变为"进行中"，开始计时
  - [ ] 点击"暂停"，当前时间段保存，任务状态变为"已暂停"
  - [ ] 点击"继续"，任务状态恢复"进行中"，开始新的时间段计时
  - [ ] 点击"结束"，任务状态变为"已完成"，停止计时
  - [ ] 每个暂停或结束操作，都会生成一个时间段记录
  - [ ] 进行中任务刷新页面后自动恢复计时
- **不包含**：多任务同时计时（串行即可）
- **优先级**：P0
- **依赖**：US-001

### US-003: 查看和调整任务时间段详情
- **作为**：用户
- **我想要**：展开任务卡片查看并调整该任务的所有时间段记录
- **以便**：了解每次工作的具体时间，并在需要时优雅地调整时间
- **验收标准**：
  - [ ] 点击任务卡片可展开/收起时间段列表（默认收起）
  - [ ] 收起状态显示："时间段列表（共N段，累计X小时X分）"
  - [ ] 展开后每段时间段显示：
    - 日期：`2026-04-21`
    - 24小时制时间轴进度条（00:00-24:00）
    - 进度条上蓝色填充部分表示该时间段
    - 进度条两端可拖拽的圆形手柄（调整开始/结束时间）
    - 原始时长和有效时长标签
  - [ ] 拖拽手柄时：
    - 实时显示当前拖动的时间点（tooltip）
    - 最小调整粒度为5分钟
    - 防止与同任务其他时间段重叠（冲突时变红提示）
  - [ ] 松开手柄后自动保存新的时间
  - [ ] 与休息时段重叠的部分在进度条上用对应颜色（黄/红）半透明叠加显示
  - [ ] 每段时间段右上角有删除按钮
  - [ ] 时间段列表底部有"+ 添加时间段"按钮（手动补录）
  - [ ] 任务卡片主区域显示该任务的原始总时长和有效总时长
- **优先级**：P0
- **依赖**：US-002

### US-004: Dashboard 统计概览
- **作为**：用户
- **我想要**：在页面顶部看到今日的工作统计概览
- **以便**：一目了然地了解今天的工作量
- **验收标准**：
  - [ ] 显示今日任务数量
  - [ ] 显示今日总有效工时（时:分格式）
  - [ ] 显示人天换算值（保留2位小数，如"0.81 人天"）
  - [ ] 显示各任务的工时占比或进度条
  - [ ] 统计数据实时更新（当任务状态变化时）
- **优先级**：P0
- **依赖**：US-002

### US-005: 固定休息时间扣除
- **作为**：用户
- **我想要**：设置每日固定的休息时段，系统自动从工时中扣除
- **以便**：得到准确的有效工作时间
- **验收标准**：
  - [ ] 可配置休息时段（名称、开始时间、结束时间、颜色）
  - [ ] 每个时间段计算有效时长 = 原始时长 - 与休息重叠部分
  - [ ] 任务总有效时长 = 所有段有效时长之和
  - [ ] Dashboard 统计基于任务总有效时长计算
- **优先级**：P0
- **依赖**：US-002

### US-006: 历史记录查看
- **作为**：用户
- **我想要**：查看过去任何一天的任务记录和统计
- **以便**：回顾历史工作量
- **验收标准**：
  - [ ] 支持按日期切换查看历史
  - [ ] 显示该日期所有任务列表和统计概览
  - [ ] 可展开查看每个任务的时间段详情
- **优先级**：P1
- **依赖**：US-004

### US-007: 数据导出与导入
- **作为**：用户
- **我想要**：将所有数据导出为文件，并在需要时导入恢复
- **以便**：备份数据
- **验收标准**：
  - [ ] 点击"导出"下载 JSON 文件
  - [ ] 点击"导入"可选择 JSON 文件恢复
  - [ ] 导入前确认是否覆盖
- **优先级**：P1
- **依赖**：无

## 12. UI/UX 设计规范（Modern Dashboard 风格）

### 12.1 整体布局
```
+--------------------------------------------------+
|  侧边栏    |  顶部标题栏（应用名 + 今日日期）       |
|  (深色)    +---------------------------------------+
|            |                                      |
|  Dashboard |   统计概览卡片行（4列网格）            |
|  今日任务  |   [任务数] [总工时] [人天] [休息段数]   |
|  历史记录  |                                      |
|  设置      +---------------------------------------+
|            |                                      |
|            |   任务列表（卡片式布局）               |
|            |   +-----------------------------+    |
|            |   | 任务A  [进行中]  [暂停] [结束] |    |
|            |   | 当前段: 01:23                |    |
|            |   | 今日累计: 3小时12分(有效2小时45分) | |
|            |   | ▼ 时间段列表                   |    |
|            |   |   09:00-11:00 | 2h | 有效1h45m |    |
|            |   |   13:30-15:42 | 2h12m | 有效2h12m| |
|            |   +-----------------------------+    |
|            |                                      |
+--------------------------------------------------+
```

### 12.2 配色方案
- **主色调**：深蓝/靛蓝（#1e293b 侧边栏背景，#3b82f6 主按钮）
- **背景色**：浅灰（#f8fafc 主内容区）
- **卡片背景**：白色（#ffffff，带阴影）
- **状态颜色**：
  - 进行中：绿色（#10b981）
  - 已暂停：橙色（#f59e0b）
  - 已完成：灰色（#6b7280）
  - 未开始：蓝色（#3b82f6）
- **休息时段颜色**：
  - 午休：暖黄（#fbbf24）
  - 晚间休息：暖红（#f87171）

### 12.3 组件风格
- **卡片**：圆角（12px）、阴影（0 4px 6px rgba(0,0,0,0.1)）、悬停效果
- **按钮**：圆角（8px）、渐变背景、悬停放大
- **统计卡片**：大数字 + 小标签，顶部彩色边框
- **时间段列表**：
  - 时间轴样式，左侧颜色竖线标记休息重叠
  - **显示格式**：`2026-04-21 09:00 - 11:30`（年月日 + 起止时间）
  - **默认状态**：收起（只显示段数统计），点击展开显示完整列表
  - **拖拽调整**：展开后每段显示可拖拽的时间轴进度条
- **字体**：系统默认字体栈（-apple-system, BlinkMacSystemFont, 'Segoe UI'）

#### 12.3.1 时间段拖拽进度条交互
为了优雅地调整时间，每段时间段展示为一个可交互的时间轴进度条：

```
展开时间段列表后：

时间段 #1                    [删除]
2026-04-21                    ▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░
09:00 ────────●───────────────●────── 15:00
              ↑                 ↑
           开始手柄            结束手柄
拖拽开始手柄 → 调整开始时间（最小粒度5分钟）
拖拽结束手柄 → 调整结束时间（最小粒度5分钟）

时间段 #2
2026-04-21
13:30 ────────●────●────────── 16:00
                   ↑
              休息时段重叠区域（黄色高亮）
```

**进度条设计规范**：
- 总长度表示24小时（00:00-24:00）
- 蓝色填充部分表示该时间段的覆盖范围
- 左右两端各有一个圆形拖拽手柄（直径16px）
- 悬停手柄时显示tooltip提示当前时间
- 拖拽时实时显示时间变化，松开时保存
- 休息时段重叠区域在进度条上用对应颜色半透明叠加显示
- 防止时间段重叠：拖拽时检测冲突，冲突时手柄变红并阻止释放

**收起状态**（节省空间）：
```
▼ 时间段列表（共3段，累计4小时35分）
```

**展开状态**：
```
▲ 时间段列表（共3段，累计4小时35分）
────────────────────────────────────────
[进度条1]
[进度条2]  
[进度条3]
[ + 添加时间段 ]  ← 手动补录按钮
────────────────────────────────────────
```

### 12.4 响应式
- 桌面端：侧边栏常驻 + 主内容区
- 平板/小屏幕：侧边栏收起为图标模式
- 不支持移动端小屏（但可横向滚动查看）

## 13. 成功标准

- [ ] 用户可以在 3 秒内创建任务并开始计时
- [ ] 同一任务可暂停/继续至少 5 次，所有时间段正确记录
- [ ] 任务卡片正确显示原始总时长和有效总时长
- [ ] Dashboard 统计概览实时更新，人天换算准确
- [ ] 休息扣除计算准确（经手工验证 5 组测试数据）
- [ ] 数据导出/导入完整无误

## 14. 风险与缓解

- **R1 单文件体积过大**：Dashboard 风格 CSS 增加体积
  - **缓解**：使用精简的 CSS 自定义属性，避免冗余样式，目标 < 150KB
- **R2 任务状态管理复杂度**：多段计时增加状态机复杂度
  - **缓解**：明确任务状态流转（idle → running → paused → running → completed），每个状态有明确的操作按钮
- **R3 时间段重叠检测**：编辑时间段时可能产生重叠
  - **缓解**：编辑时检测同任务内的段重叠，提示用户

## 15. 设计决策确认

| 问题 | 决策 |
|------|------|
| Q1：时间段列表默认状态 | **默认收起**，显示段数统计和累计时长，点击展开 |
| Q2：已完成任务能否重启 | **不允许**，completed 状态为终态，如需继续请新建任务 |
| Q3：进行中任务高亮 | **需要**，Dashboard 顶部设置"当前进行中的任务"特殊区域，同时任务卡片显示绿色边框/发光效果 |

### 15.1 当前进行中的任务高亮区域设计

在 Dashboard 顶部统计概览下方，设置一个醒目的"当前进行中的任务"区域：

```
+--------------------------------------------------+
|  当前进行中的任务                                 |
|  ┌─────────────────────────────────────────┐    |
|  │ 🔴 任务A - 进行中      已运行 01:23:45   │    |
|  │ [暂停] [结束]                            │    |
|  └─────────────────────────────────────────┘    |
+--------------------------------------------------+
```

- 固定在页面顶部，醒目背景色（如渐变蓝）
- 显示任务名、已运行时间、操作按钮
- 如果没有进行中的任务，该区域隐藏

### 15.2 任务卡片状态样式

- **进行中（running）**：绿色边框（3px solid #10b981）+ 微弱发光效果
- **已暂停（paused）**：橙色边框
- **已完成（completed）**：灰色边框，不可再操作
- **未开始（idle）**：默认无边框
