## 1. 一句话总结
为需要记录任务工时的个人用户提供一个简洁实用的 Web 计时器，支持开始/停止计时、固定休息时间自动扣除、人天换算，并支持数据本地存储和备份导出。

## 2. 背景与问题（As-is）
- **当前做法**：用户手动记录或估算任务耗时，缺乏精确追踪
- **痛点/成本**：容易遗忘、统计困难、休息时间未扣除导致工时虚高
- **为什么现在做**：需要一个轻量、打开即用的工具，无需复杂配置

## 3. 目标（Goals）
- 精确记录每个任务的工作时长（精确到分钟）
- 自动扣除固定休息时段（11:30-13:30，17:30-19:00）
- 实时显示人天换算（按 8 小时/天）
- 支持完整历史记录查看和周/月统计报表
- 数据可导出备份（JSON 格式）

## 4. 非目标（Non-goals）
- 不支持多设备云端同步
- 不支持团队协作和多用户
- 不支持自动追踪（如检测空闲时间）
- 不支持发票/计费功能
- 不原生支持移动端（但 Web 可用）

## 5. 目标用户与使用场景
### 5.1 用户画像
- **P1 个人工作者/自由职业者**：需要精确追踪自己在各个项目上花费的时间，用于客户报价或个人效率分析

### 5.2 典型场景
- **S1**：开始一天工作 → 选择任务 → 点击开始计时 → 工作 → 点击停止 → 查看今日工时和人天
- **S2**：查看历史 → 选择日期 → 查看当天所有任务记录和扣除休息后的有效工时
- **S3**：月末汇总 → 导出数据备份 → 查看月度报表了解总投入人天

## 6. 用户旅程（To-be）

**核心操作流程：**

1. **打开应用** → 浏览器访问页面 → 显示今日任务列表和计时器
2. **创建/选择任务** → 输入任务名称（或从历史任务中选择）→ 任务出现在列表中
3. **开始计时** → 点击任务旁的"开始"按钮 → 按钮变为"停止"，显示运行计时器
4. **工作中** → 计时器实时显示已用时间，休息时段用不同颜色标注
5. **停止计时** → 点击"停止" → 记录本次工作时段，更新总工时
6. **查看统计** → 页面下方显示今日有效工时、总在线时间、人天换算
7. **回看与编辑记录** → 在历史记录中点击某条记录 → 可以拖拽调整开始/结束时间，或直接修改时长
8. **事后补录** → 手动添加一条记录（输入任务名、开始时间、结束时间）→ 系统自动计算并扣除休息
9. **查看历史** → 切换到历史页面 → 选择日期查看过往记录
10. **导出数据** → 点击"导出"按钮 → 下载 JSON 备份文件

### 6.1 失败路径与边界
- **F1 浏览器数据被清除**：用户误清缓存导致数据丢失 → 系统显示空状态 → 用户可通过之前导出的 JSON 恢复
- **F2 跨天计时**：用户在 23:59 开始计时，00:30 停止 → 系统应将记录归入开始的那一天
- **F3 计时期间页面刷新**：用户不小心刷新页面 → 计时器应恢复运行状态（从 localStorage 读取当前计时状态）
- **F4 休息时间内开始计时**：用户在休息时段内点击开始 → 系统应提示"当前为休息时间"并询问是否继续
- **F5 数据损坏**：localStorage 数据格式异常 → 系统应检测并提示重置或恢复
- **F6 编辑导致时间重叠**：用户调整时间后，两条记录出现重叠 → 系统应提示冲突并允许自动合并或手动调整

## 7. 约束与假设

### 7.1 约束
- **C1 浏览器环境**：应用运行在浏览器中，依赖 localStorage 存储，存储上限约 5-10MB
- **C2 单用户**：设计为个人使用，不处理并发或多用户场景
- **C3 时间精度**：精确到分钟，不追踪秒级精度
- **C4 标准工作制**：人天换算固定按 8 小时/天计算

### 7.2 假设
- **A1 用户主要在桌面浏览器使用**（验证方式：观察用户反馈，如需要再优化移动端适配）
- **A2 用户愿意手动导出备份数据**（验证方式：在导出按钮旁提示备份重要性）
- **A3 固定休息时间适用于大多数工作日**（验证方式：提供设置入口允许用户自定义休息时段）

## 8. 方案选择

### 选择的方案：纯前端单页应用 + localStorage + JSON 导出/导入

- **做法**：HTML/CSS/JS 单页面应用，所有数据存储在浏览器 localStorage，提供 JSON 导出/导入功能
- **优点**：无需后端服务器、打开即用、实现简单、隐私性好（数据不上云）
- **缺点/风险**：数据易丢失（清缓存/换浏览器）、无法跨设备自动同步
- **选择理由**：用户明确要求浏览器本地存储，且为个人使用，无需后端复杂度

### 曾经考虑过的方案
- **方案 A（纯前端无导出）**：太脆弱，数据一旦丢失无法恢复
- **方案 C（PWA）**：增加实现复杂度，但核心体验提升有限

### 方案的比较

| 维度 | 方案 A | 方案 B（选择） | 方案 C |
|------|--------|----------------|--------|
| 实现复杂度 | 低 | 低 | 中 |
| 数据安全性 | 低 | 中（可备份） | 中（可备份） |
| 跨设备同步 | 不支持 | 不支持 | 不支持 |
| 离线使用 | 支持 | 支持 | 支持（更优） |
| 可安装到桌面 | 否 | 否 | 是 |

## 9. 核心对象/数据

- **任务记录（TimeEntry）**：
  - **来源/归属**：浏览器 localStorage，以日期为 key 存储
  - **关键字段**：`id`（唯一标识）、`taskName`（任务名称）、`startTime`（开始时间戳）、`endTime`（结束时间戳）、`date`（归属日期）
  - **生命周期**：创建（开始计时）→ 更新（停止计时或编辑）→ 删除（用户手动删除）→ 归档（历史记录长期保留）

- **休息时段（BreakPeriod）**：
  - **来源/归属**：应用配置，可用户自定义
  - **关键字段**：`name`（名称，如"午休"）、`startTime`（开始时间，如 11:30）、`endTime`（结束时间，如 13:30）、`color`（显示颜色）
  - **生命周期**：创建（首次使用默认配置）→ 更新（用户在设置中修改）

- **统计汇总（DailySummary）**：
  - **来源/归属**：由任务记录和休息时段计算得出
  - **关键字段**：`date`（日期）、`totalOnlineTime`（总在线时间）、`effectiveWorkTime`（扣除休息的有效工时）、`manDays`（人天换算值）
  - **生命周期**：实时计算，不独立存储

## 10. 范围与阶段拆分

### 10.1 MVP（本次必须做）
- 单任务计时器（开始/停止）
- 固定休息时段设置与扣除（默认：11:30-13:30，17:30-19:00）
- 今日任务列表和实时统计（有效工时、人天换算）
- 历史记录查看（按日期）
- 数据导出/导入（JSON）
- 事后补录和记录编辑

### 10.2 Later（未来可能做，但明确本轮不做）
- 周/月报表图表可视化
- 任务分类/标签
- 多任务并行计时
- 番茄钟模式
- 数据导入到 Excel/CSV
- 休息提醒通知

## 11. User Stories（MVP）

### US-001: 开始和停止任务计时
- **作为**：用户
- **我想要**：点击按钮开始和停止计时
- **以便**：精确记录我在某项任务上花费的时间
- **验收标准**：
  - [ ] 页面上有一个明显的开始/停止按钮
  - [ ] 开始计时时显示当前任务的运行时间（时:分格式）
  - [ ] 停止后自动保存一条记录到今日列表
  - [ ] 刷新页面后，如果计时中应恢复计时状态
- **不包含**：多任务并行、自动检测空闲
- **优先级**：P0
- **依赖**：无

### US-002: 固定休息时间扣除
- **作为**：用户
- **我想要**：设置每日固定的休息时段，系统从工时中自动扣除
- **以便**：得到准确的有效工作时间
- **验收标准**：
  - [ ] 可以在设置中配置休息时段（名称、开始时间、结束时间、颜色）
  - [ ] 今日统计中单独显示"总在线时间"和"有效工时（扣除休息）"
  - [ ] 时间轴/记录列表中休息时段用不同颜色标注
  - [ ] 人天换算基于有效工时计算
- **不包含**：动态休息、休息提醒
- **优先级**：P0
- **依赖**：US-001

### US-003: 人天换算显示
- **作为**：用户
- **我想要**：看到当前有效工时换算成"人天"的结果
- **以便**：直观了解工作投入相当于多少个标准工作日
- **验收标准**：
  - [ ] 页面实时显示人天数值（按 8 小时/天计算，保留 2 位小数）
  - [ ] 显示换算公式，例如"6.5 小时 = 0.81 人天"
- **不包含**：自定义人天标准（如 6 小时/天）
- **优先级**：P0
- **依赖**：US-002

### US-004: 历史记录查看与编辑
- **作为**：用户
- **我想要**：查看过去任何一天的任务记录，并能够编辑时间
- **以便**：修正错误或补充遗漏的记录
- **验收标准**：
  - [ ] 支持按日期切换查看历史记录
  - [ ] 可以修改已有记录的开始/结束时间
  - [ ] 可以删除某条记录
  - [ ] 可以手动添加新记录（事后补录）
  - [ ] 编辑后统计自动重新计算
- **不包含**：批量编辑、撤销操作
- **优先级**：P1
- **依赖**：US-001

### US-005: 数据导出与导入
- **作为**：用户
- **我想要**：将所有数据导出为文件，并在需要时导入恢复
- **以便**：备份数据，防止浏览器数据丢失
- **验收标准**：
  - [ ] 点击"导出"按钮下载 JSON 文件，包含所有历史记录和设置
  - [ ] 点击"导入"按钮可选择 JSON 文件恢复数据
  - [ ] 导入时提示是否覆盖现有数据
- **不包含**：云同步、自动备份
- **优先级**：P1
- **依赖**：US-001

## 12. 成功标准

- [ ] 用户可以在 3 秒内开始计时（打开页面 → 点击开始）
- [ ] 计时误差不超过 1 分钟（考虑页面刷新等场景）
- [ ] 休息扣除计算准确（经手工验证 5 组测试数据）
- [ ] 人天换算显示正确（8 小时 = 1.00 人天）
- [ ] 数据导出/导入完整无误（导出后再导入，数据一致）

## 13. 风险与缓解

- **R1 浏览器数据丢失**
  - **缓解**：提供显眼的导出按钮和备份提醒；定期（每周）提示用户导出备份
- **R2 localStorage 容量不足**
  - **缓解**：估算存储上限（约 5MB 可存数年记录）；如接近上限提示用户导出并清理旧数据
- **R3 用户忘记停止计时**
  - **缓解**：在次日打开应用时检测跨天计时，提示用户确认并自动截断到当天 23:59
- **R4 时间重叠导致统计错误**
  - **缓解**：编辑记录时检测时间重叠，提示用户并提供自动合并选项

## 14. 未决问题

- **Q1**：休息时段是否支持跨午夜（如夜班场景 23:00-01:00）？
- **Q2**：人天换算是否需要支持自定义每日工时标准（如 7.5 小时/天）？
- **Q3**：是否需要任务模板/常用任务快速选择？
- **Q4**：历史记录是否需要搜索/筛选功能？
